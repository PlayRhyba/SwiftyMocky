Changelog

All changes to SwiftyMocky project will be documented in this file.

4.3.1 / 2026

Added:

  • Swift Testing support: inside a @Test, Verify failures and missing stubs are reported with Issue.record at the failing line (no XCTest interop needed); outside Swift Testing they go to XCTest as before
  • Mocks for protocols that inherit Sendable (directly or through another protocol) are generated as public final class …: Mock, @unchecked Sendable, so protocols like protocol DataProviding: Sendable { func getData<T: Decodable>(from url: String) async throws -> T } can be mocked in Swift 6 mode
  • All generated mocks keep their mutable state (invocations, givens, performs, stubbed property values, matcher, policies, file/line) in a private MockState struct inside a LockedValue (now public), so it can only be reached under the lock. Parameter matching and perform closures run outside the lock. Previously only method invocations were synchronized
  • Matcher is thread-safe (@unchecked Sendable): registered comparators and the failure location are lock-protected

Changed:

  • A missing stub (or another fatal mock error: no comparator registered, failed return-value cast) now traps with fatalError instead of calling exit(0), so a test run can no longer stop midway with a success exit status. FatalErrorUtil.set still allows a custom handler
  • rake test regenerates templates, CLI assets and mocks, then runs swift test (was ice test)
  • MockError.notStubed renamed to MockError.notStubbed; the old name is kept as a deprecated alias, so existing code and previously generated mocks still compile
  • Removed the unused standalone Shared SwiftPM target (its sources are compiled into SwiftyMocky and SwiftyPrototype)
  • SwiftyPrototype: MockyAssert default file: argument is now #filePath (was #file), matching SwiftyMocky
  • MockyAssert/MockyAssertion and SwiftyMockyTestObserver live once in shared sources; SwiftyPrototype keeps its no-XCTest behaviour via the SWIFTY_PROTOTYPE compilation condition
  • SwiftPM test suite now includes async method and throwing getter examples (stale macOS 12 excludes removed)
  • Renamed test target RuntimeLibaryTests to RuntimeLibraryTests
  • Example project: async method and throwing getter examples moved from Swift5.5 to Concurrency (no longer @available-gated) and are part of the iOS, macOS and tvOS targets; removed the separate Mocky_Example_iOS_15 / Mocky_Tests_iOS_15 targets, their schemes and the IOS15 flag

Fixed:

  • Missing subscript stub failure printed the literal text noStubDefinedMessage instead of the actual message

4.3.0 / 2026

Breaking:

  • Dropped CocoaPods and Carthage support - SwiftyMocky and SwiftyPrototype are distributed via Swift Package Manager only (CLI via SPM, Mint or make)

Requires

Requires Sourcery 2.4.1 (templates header Required Sourcery: 2.4.1)
  • Package requires swift-tools-version 6.0 and macOS 14 (XcodeProj 9 requirement)
  • Built in Swift 6 language mode. Generated mocks compile in Swift 6 mode and require a Swift 5.10+ compiler (nonisolated(unsafe))
  • file: default arguments use #filePath instead of #file, so failures are reported at the right location in Swift 6 mode
  • Removed unused CLI constant kSwiftyMockyCommand; kSourceryVersion and kDefaultSourceryCommand are now let

Concurrency:

  • Matcher.default, Matcher.fatalErrorHandler, MockyAssertion.handler and internal fatal-error/test-observer state are now lock-protected (same public API)
  • Generated mocks: static stubbing state is nonisolated(unsafe); getter helpers no longer shadow a generic mock’s T

ExistentialAny:

  • Generated mocks compile cleanly with the ExistentialAny upcoming feature (willThrow: any Error...)
  • Optional existentials are generated as (any P)? / (any P)!. Sourcery 2.x normalizes them to any P?, which compilers before Swift 6.4 reject
  • The project itself builds with ExistentialAny enabled, and the example project covers any P in every supported position

Changed:

  • Updated dependencies: XcodeProj 9.17.8, Yams 6.2.2
  • Example project consumes SwiftyMocky as a local Swift package

Fixed:

  • cli: excluded files in Mockfile were ignored by Sourcery 2.x (relative / differently-cased paths)
  • cli: INFOPLIST_FILE lookup with XcodeProj 9 build settings
